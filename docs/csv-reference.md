# CSV input reference

What each converter expects in the header row, and what happens when a column is
absent.

## How columns are matched

1. **Headers are whitespace-normalized** (`src/data_cleaning.normalize_header`)
   before anything else, on both the preview path and the conversion path. A
   trailing space in an export header does not break the lookup, and the preview
   UI cannot disagree with what the converter actually reads. Invisible format
   characters (a zero-width space, a stray BOM) are removed from headers too.
2. **The file is decoded as strict UTF-8, falling back to Windows-1252.** An
   Excel "CSV UTF-8" export (with its BOM) and a plain "CSV (Comma delimited)"
   export from Windows Excel (the system code page, cp1252) both decode
   correctly; a UTF-16 "Unicode Text" export is recognised by its BOM. Every
   read in the worker and the converters decodes the same way
   (`src/data_cleaning.decode_csv_bytes`, which drops a BOM), so a BOM never
   turns the first header into `﻿Contact ID`. Before the fallback existed, every accented
   character in a cp1252 export became `�` silently. The command line
   (`run.py`, `src/main.py`) decodes the same way
   (`src/data_cleaning.decode_csv_bytes`) and records a file-level warning when
   it falls back to Windows-1252; it used to stop at the first accented name.
   A damaged UTF-16 file converts with a file-level warning: bytes that are not
   text are read as `�`, and a stray byte that leaves the file an odd number of
   bytes long is left out (it used to become a last row of `�`). The web app
   decodes the upload itself (`apps/web/src/lib/csv-decode.ts`) and leaves the
   stray byte out too; it kept it until 2026-10, and in a file without a final
   newline the `�` was filed as part of the last cell. Both decoders are held
   to one table of cases, `tests/fixtures/csv_decoding_cases.json`. The web
   does not pass on how it decoded a file, so its results page does not show
   the encoding warnings the command line records.
3. **Any column mapping you saved is applied first**, then required-column
   validation runs. A CSV you have correctly mapped is never rejected for a
   column name it no longer uses. The mapping is matched against the headers
   as normalized in step 1, as the mapping page shows them, so a header with a
   stray space is still renamed; a mapping entry for a column the CSV doesn't
   have is reported as a warning.
4. **Mapping entries whose target is not an expected column are dropped.** A
   mapping that renamed a real header to an internal key (`{"Class/Event ID":
   "event_id"}`) would rename the column out from under the converter, so such
   entries are ignored rather than applied.

## How cells and rows are read

- **A cell with no value in it is blank**: an Excel error (`#N/A`, `#REF!`,
  `#VALUE!`, `#NAME?`, `#DIV/0!`, `#NULL!`, `#NUM!`, and the newer `#SPILL!`,
  `#CALC!`, `#ERROR!`), or a cell of only whitespace and invisible characters
  (zero-width space, BOM, direction marks, control characters) or `�` (bytes
  that weren't text, so a damaged ID is not filed as the ID). The column's
  usual blank-cell handling then applies — a row whose ID is `#N/A` is left out
  with a "Missing required" error, a blank `LocationCode` gets the default — and
  one file-level warning counts the Excel errors and names the first. Cells
  that held only invisible or unreadable characters get one file-level warning
  per column, naming the rows and the characters (`U+0001`), so a default filed
  for one is never silent. A cell of ordinary spaces is just blank.
- **A row that is not a record is skipped, with a warning naming it**
  (`data_validation.non_record_reason`): a blank row (a line of commas, or the
  `""` lines around a report footer), a row repeating the header row (two
  exports pasted together), and, in a file of three or more columns, a row with
  a single filled cell — a report's title or footer line, such as the report
  name, copyright, "Confidential Information" and "Generated By" lines
  Salesforce adds. Row numbers in every other issue are unchanged.
- **Identifier cells** (`Contact ID`, `Activity ID`, `Member ID`,
  `Class/Event ID`) lose invisible format characters, and control characters
  become a space as they would in the XML, with a `standardized_value` warning
  naming the characters: with them the ID is a different one from the one shown.
  Training groups events on the cleaned ID.
- **A row with more values than the header has columns** is read up to the last
  column; one file-level warning names the rows (the first five) and, for a
  single row, the values dropped. Its other values may be shifted by an
  unquoted comma, so check it. A row with fewer values is normal — exports leave
  trailing blank cells off — and is not reported.
- **A cell holding what look like further rows** — lines with as many commas as
  a row of the file — is reported as an error naming the row and column: a
  quotation mark was opened and never closed, and the rows it swallowed are
  missing from the XML. (Past 131,072 characters the file can't be read at all.)

## Requirement tiers

Defined once in `apps/worker/app/services/column_requirements.py` and shared by
the mapping page and the conversion.

| Tier | Column missing means | Where it shows |
|---|---|---|
| **Required** | Conversion fails with HTTP 422 naming the columns | Red on the mapping page; the convert button is blocked |
| **Conditional** | Warning — needed only when a related field has a particular value | Amber on the mapping page |
| **Fabrication-risk** | Warning — the converter will emit a non-empty default into your filing | Amber on the mapping page |
| **Optional** | Element is omitted | Not flagged |
| **Extra** | Column is ignored entirely | Listed as "extra" on the preview page |

Extra columns are harmless. The preview page also runs a fuzzy match (difflib,
0.6 cutoff) between missing and extra columns and suggests renames — that is what
catches `Zip Code` vs `Zip/Postal Code`.

## Counseling (Form 641)

**Required (12).** Missing any of these fails the conversion:

`Contact ID` · `Race` · `Ethnicity:` · `Gender` · `Disability` ·
`Veteran Status` · `Currently In Business?` · `Type of Session` ·
`Language(s) Used` · `Date` · `Name of Counselor` · `Duration (hours)`

> `Ethnicity:` really does end with a colon — that is the Salesforce export
> header, and it is matched literally.

`Activity ID` is not required, but it is the session number SBA receives
(`PartnerSessionNumber`). A blank cell files an empty one and is reported as a
warning on its row; a file without the column gets one warning instead. A blank
`First Name` is reported the same way as a blank `Last Name`.

**Conditional (9).** Each is required only in a particular case:

| Column | Required when |
|---|---|
| `Branch Of Service` | military status indicates service |
| `Internet (specify)` | the contact medium is Internet (filed in the `Internet` element) |
| `InternetUsage` | the contact medium is Internet and `Internet (specify)` is blank (older column, used as its fallback) |
| `Legal Entity of Business` | the client is in business |
| `Other legal entity (specify)` | legal entity is `Other` |
| `FIPS_Code` | Rural/Urban is set |
| `Nature of the Counseling Seeking?` | the client is in business |
| `Nature of the Counseling Seeking - Other Detail` | counseling sought is `Other` |
| `Other Counseling Provided` | counseling provided is `Other` |

A filled cell its case doesn't call for is left out of the XML with a warning
that says why, from the value as read: `Army` beside a Veteran Status of `No`,
or of `Retired` (not a recognized status), or a `FIPS_Code` beside a blank
`Rural_vs_Urban`. A `Branch Of Service` that names no branch (`N/A`, `None`,
`No military service`, `Prefer not to say`) is left out without one.

**Fabrication-risk (9).** Absent → a non-empty value is invented. See
[converters.md](./converters.md#fabricated-defaults) for the exact values.

**Full expected set (74 columns).** These are the headers the converter reads;
anything else is extra.

## Training (Form 888)

**Required (1):** `Class/Event ID`.

The worker does **not** hard-fail on the exact spelling for this converter,
because the converter resolves the column through aliases and flags a missing
event id itself. An exact-match check here would reject valid aliased uploads.

**Alias-based matching.** Each field accepts several spellings; in each row,
the first one that is filled wins, and issues name the spelling your file
uses. An event-level field (name, start date, funding source, topic, type,
cosponsor, `LocationCode`) is taken from the first of the event's rows that
has it, with a warning when rows disagree. For the start date, funding source,
topic, type and `LocationCode` it is the first row whose value can be filed —
a date that parses, a code SBA accepts — and two spellings of one value
(`1/15/2025` and `2025-01-15`) are not a disagreement:

| Field | Accepted headers |
|---|---|
| Event ID | `Class/Event ID` |
| Event name | `Class/Event Name` |
| Start date | `Start Date` |
| Funding source | `Funding Source` |
| Training topic | `Training Topic` |
| Event type | `Class/Event Type` |
| Cosponsor | `Cosponsor`, `CosponsorsName`, `Partner Organization` |
| City | `City`, `city` (a street-address column is not read as the city) |
| State | `State/Province`, `State`, `state` |
| ZIP | `Zip/Postal Code`, `Zip`, `zip`, `ZipCode`, `Zip code` |
| In business | `Currently in Business?`, `Currently in Business`, `In Business` |
| Gender | `Gender`, `gender`, `Sex` |
| Disability | `Disabilities`, `Disability`, `Has Disability` |
| Military | `Military Status`, `Military`, `Veteran Status` |
| Race | `Race`, `race`, `Racial Background` |
| Ethnicity | `Ethnicity`, `ethnicity`, `Ethnic Background` |

The mapping page shows the first spelling of each as the "expected" name.

An optional `LocationCode` column is also read, as on the counseling form; without
it every event is filed under the configured location code.

**No total columns are needed.** Supply one row per attendee; the converter
computes female/male, race, ethnicity, veteran, disability and business-status
totals per event. A `Veteran Status` checkbox (Yes/No, true/false, 1/0) counts
as veteran or no service, as on the counseling form. A Race or Military Status
answer no count takes — "Two or More Races", "Multiracial", "Hispanic or
Latino" as a race, "Retired" — is counted under none and named in one warning
per event; answers that decline the question are not reported.

**Location.** An event's location is the first of its rows with a city, a
state and a ZIP, else the first with a city and a state. The ZIP may sit
anywhere in its cell (`IA 50010`) and inside Excel's leading-zero forms
(`="05030"`, `'05030`); a ZIP+4 may be written `50309-1234`, `50309 1234`,
`503091234` or with a dash (`50309 – 1234`). Five digits inside a longer run of
digits — a phone number — are not a ZIP. Text in the cell besides the ZIP is
left out with a warning. When no row's ZIP can be read, the city and state are
filed without one (`ZipCode` is optional), with a warning. Only when no row
gives both a city and a state does the whole `TrainingLocation` fall back to
`TrainingConfig.DEFAULT_LOCATION`, with a `FABRICATED_DEFAULT` warning naming
what the rows did give. Rows that give different addresses are not reported:
in a campaign-member export each row's address is that attendee's own.

**Funding source** must match an SBA funding code exactly (case-insensitively).
A partner's own label — `CORE`, `Federal` — is **omitted from the XML** with a
warning, because `FundingSource` is optional and a non-enumerated value would
fail schema validation. The accepted list is `VALID_FUNDING_SOURCES` in
`src/config.py`.

## Training client (Form 641 from training rows)

**Required (2):** `Class/Event ID`, `Contact ID`.
**Conditional (1):** `Member ID` — the per-attendee session id. Without it, every
attendee at an event shares the event id as their session number; a row with
neither is reported as a warning.

**Expected set (28 columns),** in the order the converter declares them:

```
Class/Event ID              Related Record ID
Member Type                 Training Topic
First Name                  Class/Event Type
Last Name                   Funding Source
Member Status               Member ID
Company                     Class Teacher
Phone                       Contact ID
Email                       Street
Unique Campaign Members     city
Currently in Business?      State
Ethnicity                   Zip code
Race                        Start Date
Disabilities                Class/Event Name
Gender
Military Status
```

Note the inconsistent casing — `city` is lowercase while `State` and `Zip code`
are not. That is what the Salesforce export produces, and the headers are matched
literally, so reproduce them exactly or map them.

**Renames applied internally** before the counseling converter sees the row:

| Your column | Read as |
|---|---|
| `Phone` | `Contact: Phone` |
| `Company` | `Account Name` |
| `Street` | `Mailing Street` |
| `city` | `Mailing City` |
| `State` | `Mailing State/Province` |
| `Zip code` | `Mailing Zip/Postal Code` |
| `Disabilities` | `Disability` |
| `Military Status` | `Veteran Status` |
| `Ethnicity` | `Ethnicity:` |
| `Class/Event ID` | `Activity ID` |
| `Class Teacher` | `Name of Counselor` |
| `Start Date` | `Date` |
| `Currently in Business?` | `Currently In Business?` |

A blank cell never erases a value already there: with both `Start Date` and
`Date`, a row whose `Date` is blank keeps its start date, and each row uses the
last of the two that has a value. A file with both gets one warning naming them.

Everything the counseling schema needs but a training export does not carry is
supplied from `TrainingClientConfig.DEFAULTS` — mostly empty strings, plus
`Type of Session: Training`, `Language(s) Used: English`,
`Services Provided: Business Start-up/Preplanning`, and zeroed hours and loan
amounts. A default also fills the blank cells of such a column when the CSV has
one; the file-level warning listing the defaults says so for that column.

## Data-quality checks on the preview

Before you convert, the preview page reports counts for each problem it can see
in the first rows, with a severity and the column responsible. It is generated by
`src/data_validation.py` and only lists checks with a non-zero count, so an empty
data-quality panel means nothing was detected — not that nothing was checked.
It reads cells and rows as the conversion does (see
[How cells and rows are read](#how-cells-and-rows-are-read)): an ID of `#N/A`
counts as missing, and rows that are not records are counted under
`not_a_record` rather than as rows missing their ID. A cell an unclosed quote
filled with further rows (`unclosed_quote`, an error) and rows with values past
the last column (`extra_values`) are counted too.

Duplicate headers are preserved rather than deduplicated when the header row is
read, so two columns collapsing to the same normalized name can be detected
instead of one silently shadowing the other. Conversion records a file-level
warning naming each repeated header, and each row takes the last of those
columns that has a value: a blank second `Date` column no longer erases the
first (`src/data_cleaning.NormalizedDictReader`, used by the converters, the
preview and the cleaning diff alike).
